# AI-4a — morning recap: facts, validated model draft, template fallback, preview, history, schedule tick

Branch `reinvent/ai4a-recap` off `main` `286bf1c4`. Package AI-4a of the H2 reinvention plan
(`~/.claude/plans/staged-dazzling-dongarra.md`, "Recap", "SMS", "Jobs"). The recap text is **written from facts that code computes**; a
model may only phrase them, and code refuses any text that carries a number the facts do not. With the fake provider and
`SMS_PROVIDER=console` (the defaults) nothing leaves the server.

## Content rules (both paths — model and template)

| Rule | Where it is enforced |
|---|---|
| Yesterday's discretionary total, then up to 3 top categories by name | facts (`spentYesterday`); template; prompt |
| "On track / Tight / Over plan this week" from `withinPlan`; nothing when `null` | template; prompt |
| "$X free until payday (Fri)" from `availableUntilPayday`; "free through Saturday" with no payday; nothing when `null` (never a false zero) | template; prompt |
| Bills due in the next 3 days: name, amount, day or "tomorrow"/"today" | facts (`billsNext3Days`); template shows 2, then "and more" |
| "N charges need a look" when `needsLookCount > 0` (spine review + categorizer review) | template; prompt |
| At most ONE next step, chosen by code: review, else a bill due tomorrow, else none | `facts.nextStep`; template; prompt |
| Stale bank: "Bank data last updated N days ago; figures may be incomplete"; **never "nothing spent"** when stale | template (pinned by test); prompt |
| Late arrivals: "Arrived late: $X from Mon" (older rows created after the previous recap) | facts; template; prompt |
| One progress line only when a flag is set (debt payment posted, or spending lower than the same span last week); no other praise | template; prompt |
| At most one open finding, one fixed sentence, never one already surfaced, never the stale-bank one (told above) | template; prompt |
| No guilt, no exclamation marks, no emojis, no questions; forbidden phrases rejected | validator |
| No account numbers, no merchant strings, no debt balances or amounts owed | facts carry category/bill names only (`safeName`: letters and a few marks, ≤ 20 chars), `%` paid never a balance; validator rejects any unknown number |
| The link is appended by code | `generate.ts` |
| Every number in the text comes from the facts | `validate.ts` (property-tested: 1,000 random fact sets, the template always passes) |

## Rules that hold

- **A model never computes a figure.** It sees the facts as data and writes words; any number not in the facts fails validation, and a failing draft gets one retry with the reason, then the template. A model that is off, over budget, refuses, or times out also ends in the template.
- **A recap is sent only through `sendRecapDelivery`.** Consent, opt-out, pause, the global daily cap and "one scheduled text per member per day" (partial unique index) are AI-4b's. The tick only decides when to *ask*.
- **Never twice.** `recaps` is unique per `(user, day)`; `recap.send` is keyed `recap:<user>:<date>`; the delivery row is inserted before the provider is called. A delivered recap is never resent; retries only from a `failed` delivery with `attempts < 3`, 60 s apart.
- **Local time per member.** Each member's date and send instant come from their own `timezone` and `send_time_local` (07:00 on 3/8 and 11/1 pinned for Central and Eastern). `skip_weekends` and `paused_until` are honoured.
- **Preview stores nothing** (no `recaps`, `recap_deliveries` or `agent_runs` row); its model call still counts against the household's daily `recap` cap because `runStructured` records it.
- **Household and member isolation.** Every query is scoped by `household_id` (and `user_id` for history); a send job cannot reach another household's recap; `generate-now` is owner-only and only for members of the owner's household.
- No debt balance or amount owed is read into the facts (only the spine's `%` paid and a count of payments); no merchant description is read into the facts or the prompt.

## Questions for the lead

1. **The daily `recap` cap is 3 calls per household** (`DEFAULT_DAILY_CAPS`). One generation that needs its retry uses 2, so two members in one household — plus a preview — exhaust it, and the later ones fall to the template (safe, but silent). Raise the default (10?) in `ai/budget.ts`, or set `ai_budget.daily_caps` per household? Not changed here.
2. **There is no `payment_state` column.** "Confirmed debt payment yesterday" is a *posted* (not pending) outflow tagged to a debt (`debt_id`), dated yesterday.
3. **The categorizer hook.** PR-A is not on this base and a bundled server cannot probe for a missing module, so `facts.ts` exports `registerCategorizationReviewCount(fn)`; the count is 0 until PR-A's package calls it at boot with its review counter.
4. **Position is as of now.** `weekToDate` and `position` come from today's curve; `forDate` only sets "yesterday", the bills window and the link. A `generate-now` for a past day therefore pairs old rows with today's position.
5. **A 6-hour grace window** (my addition): a recap not sent within 6 h of its send time is marked `skipped` rather than texted that evening.
6. **A delivery row left `queued`** by a crash between its insert and the provider call is never retried (a retry could double-text). `sendSms` only reclaims `failed` rows; unchanged from AI-4b.
7. **A daily-cap refusal** leaves `attempts` at 0 (AI-4b), so the tick retries it every 5 minutes until the grace window ends or the cap lifts.
