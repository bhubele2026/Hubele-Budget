## Round 3 (same day): verified is not "left unchanged", and the whole backlog files up to today

- The reviewer's objection stands: a model category nobody checked for 14 days proves nothing. Such a suggestion is now **unreviewed**: it leaves the review queue, the charge stays provisional, and it never counts toward the 30-verified or 9-in-10 requirements nor feeds the model's priors. Requirement wording now says "you verified in Review".
- Household › Automation gains **Backlog** ("Unfiled charges: N · oldest <date>", button "File everything up to today", owner only) and **Bank data** (each bank's data-through date and whether automatic updates are on). The run files every unfiled, unlocked charge from the oldest, deterministic stages first, then the model pass when AI is on; the result line reads "Filed N · Suggested M (provisional) · K need a look · J left unchanged".
- Brad's one click after deploy: Household → Automation → Backlog → File everything up to today. Without `AI_ENABLED=true` the leftovers sit in Review; with it the model suggests provisionally.

## What changed in round 2 (reviewer's items)

1. **Automatic categorization is usable.** The only switch in the app used to write a per-user preference the server never read. Now `GET/PUT /categorization/settings` reads and writes the two switches the engine actually uses (owner only for writes), and reports mode (Off / Suggests / Files on its own), the requirements with progress, engine counts and the last 20 decisions with undo. Eligibility is cumulative and stable instead of a rolling month: 30 model suggestions judged (lifetime), 9 in 10 right among the last 50, held open while the last 20 stay at 8 in 10. A provisional model filing you leave unchanged for 14 days counts as judged (never as a prior for the model). Your own picks lock the row; bank sync never overwrites a category; pending-to-posted keeps the filing; reprocessing adds no second decision (unique transaction + input hash); corrections teach merchant memory, which beats rules next time.
2. **Morning texts are honest end to end.** Console mode is **preview**, never "sent": the API maps console deliveries to "previewed", test-send answers "previewed", history says "Preview — not sent", the Recap screen shows a six-row ladder (Preview mode · Provider configured · Phone verified · Scheduled 7:00 AM Chicago · Accepted by carrier · Delivered/Failed). The text now carries a code-chosen action line (hold non-essentials / shortfall / charges to review / bill tomorrow / extra toward the highest-APR debt / nothing to do). Default schedule 7:00 America/Chicago; the stale-bank line replaces "nothing spent" when the bank has not reported.
3. **Bank updates reach the app without opening it.** The Plaid webhook existed but banks linked before the address was set never notified. Every bank now gets the address through the free `/item/webhook/update` (at boot and after each sync, rechecked weekly); Household › Banks says "Automatic updates: On" or why not; `/api/healthz` says whether the address is set. No new billable call; the paid refresh stays behind the explicit confirm.
4. **Debt freedom is in the daily experience.** Today reads: Room in the plan (not "free cash"), This week, One thing, Debt (percent paid, "paid down … confirmed by the bank", new charges, payments that did not reduce debt), then the rest. When the week is over, the card offers "Pick a way back": hold, trim a category, or carry the overage into next week (lowers next week; nothing ever raises a budget). Payoff ranges keep their assumptions behind "What this assumes".
5. **Live AI** — see "Live checks" below.
6. **Journeys** — see "Journey walk" below. Detours into classic: bills now open `/plan/bills`; Today's classic link moved to Household › Classic tools; the Automation screen replaces the dead switch; the What's-new sheet points there.
7. **Docs and deployment agree** — this note; stale "sync only on click" comments fixed in `render.yaml` and `index.ts`.
