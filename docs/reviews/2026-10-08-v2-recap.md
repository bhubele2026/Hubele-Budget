# V2 — Morning text honesty and the one-action line

Branch `finish/v2-recap`, base `2b664f6c`. No migration. No new dependency.

## What changed
- `getSmsConfig()` now returns `{ provider, configured, mode }`. `mode` is `live` only when the provider is twilio and every credential is set; console and fake are `preview`. Console is no longer "configured".
- `/api/healthz` exposes `sms.mode`.
- `GET /recap/settings` adds `delivery`: mode, providerConfigured, phoneVerified, scheduled (enabled, verified, not opted out, not paused), sendTimeLocal, timezone, lastDelivery `{status, provider, at}`.
- Deliveries and history items carry `provider`. A console row is mapped to `previewed` by the API; the DB value (`sent`) is untouched. A recap whose delivery was a console row reads `previewed`, never `sent`.
- `POST /recap/test-send` answers `{status:"previewed", mode:"preview", text}` in preview (the console row is still recorded) and `{status:"sent", mode:"live", text:null}` live. The fake provider counts as live for this call, so tests can reach the live branch.
- New `recap/action.ts`: `pickAction(facts)`, first match wins: stale none; over plan hold; shortfall gap; charges need a look; bill due tomorrow; on plan + payday within 3 days extra toward the highest-APR debt; else nothing to do. `facts.action` rides in the facts; the template puts it after the plan line.
- Template wording: "Room in the plan: $X until <Fri|Saturday>".
- Prompt `recap.v2` (v1 stays registered; v2 is newest and runs). A model draft that leaves the action out gets it appended by code; if that no longer validates (too long) the template speaks instead.
- Template now marks a finding surfaced only if its sentence survived the length cut.

## What a user sees
Preview (today): a six-row ladder on the Recap page: Preview mode (Yes, with "Texts are written to the server log. Nothing is sent until SMS is set up."), Provider configured (No), Phone verified, Scheduled (7:00 AM Chicago, or Off), Accepted by carrier (No), Delivered ("Preview — not sent"). Test text: "Preview shown. No text was sent." plus the text. History: "Preview — not sent".
Live: five rows (no Preview row); Yes/No from the last real delivery; "Failed" row when the carrier did not deliver; test text: "Test text sent."; history keeps Sent / Delivered / Failed / Drafted.

## Decisions to check
- Shortfall finding payloads carry no bill name, only `shortBy`. The action says the gap ("Cash may dip $X under the buffer before payday"); the bill name is not available without a monitor change.
- Action (d) uses `needsLookCount` (spine review + categorizer), matching the existing "N charges need a look" line; the template drops its own review line when the action is that line.
- (f) and the "On plan." prefix apply only when `withinPlan` is `yes`; `tight` or unknown reads "Nothing to do today."
- (b) names Sunday as the weekend day (the household week runs Sunday to Saturday).
- Shortfall action repeats each morning while the finding is open (it is true each morning); the finding line itself is not repeated.

## External blocker
Twilio Sole Proprietor registration. Set on the web service: `SMS_PROVIDER=twilio`, `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_MESSAGING_SERVICE_SID` (or `TWILIO_FROM`), `SMS_WEBHOOK_BASE_URL` (public https base). With all five, `/api/healthz` shows `sms.mode: "live"` and the Preview row disappears. Missing any one keeps `preview` and logs one warning.
