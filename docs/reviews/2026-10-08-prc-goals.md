# PR-C — goals and reserves: the goals table, money reserved in checking, the buffer goal, the weekly limit's goals line, `goal_behind`

Branch `reinvent/prc-goals` off `main` `6b4fc1c1`. Migration range 0080–0089 (uses `0080_goals.sql`).
No model calls anywhere in this package: every figure is computed in code from stored rows.

## The owner's decisions this package rests on

- **Code computes every figure** (CLAUDE.md §1). No model writes, raises or sizes a goal; the endpoints are the only writer.
- **"The forecast may read low, never high."** A reserve only ever LOWERS available: a negative typed amount counts as 0,
  a goal backed by an account never counts (that money is not in checking), an unknown account balance is `null`, never 0.
- **Plan › goals bullet:** `goals` (savings/buffer/sinking) with `reserved_in_checking` subtracting from available.

## Definitions

| Figure | Definition |
|---|---|
| reserve (per goal) | `max(0, manual_current_amount)` when **active ∧ reserved_in_checking ∧ no plaid_account_id**; else 0. |
| `reservesHeld` | Σ reserves. `availableUntilPayday = max(0, lowest − buffer − reservesHeld)`; `safeToSpendNow = max(0, min(remainingWeek, available))` (unchanged formulas, PR-B1). |
| `goalsMonthly` | Σ `max(0, monthly_contribution)` of **active** goals → the derivation's "Goals" line. |
| current | the backing account's balance (owner's `forecast_settings.account_snapshots[plaid_accounts.id]`, only for an account of this household) — `null` until known; else `manual_current_amount`. |
| percent | ⌊current ÷ target × 100⌋, clamped 0–100 (reads low). |
| months to target | a RANGE, never a date: n = ⌈remaining ÷ contribution⌉ → `low = n − 1`, `high = n`; null at a $0 contribution; 0–0 when reached. |
| required pace | remaining ÷ (days left × 12 ÷ 365), rounded UP to the cent; the whole remaining once the date has come. |
| behind / `goal_behind` | active ∧ target ∧ target date ∧ known current, and `remaining × 365 × 10 > contribution × 12 × 12 × days left` (required > 1.2 × contribution); a past/today date with money to go is behind. Severity `watch`, confidence `estimate`, dedupe `goal_behind:<goalId>:<YYYY-MM>`; payload ids and figures only (no goal name). |
| buffer goal | `kind = 'buffer'`: its target is served beside `forecast_settings.cash_buffer` (`Goal.cashBuffer`, `GoalList.cashBuffer`). **It never changes the buffer**: the ledger reads the buffer from `forecast_settings` alone (tested: creating one leaves `cashBuffer` and available unchanged). |
| `goalsOnTrackCount` | goals whose `behind === false` (judgeable and not behind). |
| DELETE | a goal that holds a reserve on its record (reserved ∧ no account ∧ amount > 0, any status) is **archived**, not deleted; else deleted. Archiving releases the reserve (only active goals hold one). |
| backing account | must be one of the household's `depository` accounts, never `subtype = checking`, never the bank-snapshot account → else 400. |

## Residuals

- Files touched beyond the brief's list, each required: `avalanche-core/src/goals.ts` (+ index export; the pure rule shared
  by detector, metrics and views), `allowancePlans.ts` (the caller that passed 0), `monitor/types.ts` + `facts.ts` (the
  detector's facts), `availableToSpend.ts` (comment only).
- `name`, `kind`, `status` are NOT NULL (the brief listed no nullability; a null status would escape its CHECK).
- `plaid_account_id ON DELETE SET NULL`: a retired account row turns its goal into a typed-amount goal; if it was flagged
  reserved, its typed amount then enters the reserve (reads low, never high).
- A backing account's balance is the owner's per-account snapshot; until one exists, current/percent are null and the goal
  is not judged (`goal_behind` silent).
- Nothing moves a goal to `reached` automatically (no job writes goals); the household sets it.
- AI-3's review note still lists `goal_behind` as a TODO; that note is AI-3's and was left as is.
