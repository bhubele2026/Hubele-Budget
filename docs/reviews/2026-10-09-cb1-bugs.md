# CB1 bug fixes (2026-10-09), from parity-verified section 4

Bug fixes only. No restyle, no query-size change, no money logic. No API file changed.

- D2 Amex hide-reviewed. Cause: the stored `amex.hideReviewed` value filtered rows with no control on screen. Fix: a visible "Hide reviewed" toggle (aria-pressed, note when active) above the ledger; it writes the same key. Test: `amexHideReviewedToggle.test.tsx` (stale "1" hides rows, toggle restores them and clears the key).
- D5 Chase row "Remember". Cause: `onCategoryChange={(id) => ...}` dropped the second argument. Fix: `handleQuickCategorize(tx, id, remember)` sends `rememberPattern` on the same `useUpdateTransaction` PATCH Amex uses, with the same "Categorized & remembered" toast. Test: `chaseRowRemember.test.tsx`.
- D6 `/forecast#bucket`, `#register`. Cause: `activeTab` was never read (there are no tabs; the bucket is the `/review` route). Fix: `hashTabRedirect` (`pages/forecast/hashTab.ts`) sends `/forecast#bucket` to `/review` and `/review#register` to `/forecast`, on load and on hashchange; both Chase links now point at `/review`. Tests: `forecast/hashTab.test.ts`, link href in `chaseRowRemember.test.tsx`.
- D13 `/bills/all` edit (DATA hazard). Cause: `toFormState` mapped quarterly/annual to monthly (so a save rewrote the cadence) and `buildPayload` never sent `amountKind` or kept `dayOfMonth`. Fix: quarterly/annual are real form values and menu items, `amountKind` and the stored day of month ride the form and the payload (pause/resume sends `amountKind` too). Test: `billsOneTimeMove.test.tsx` "(D13)" - a quarterly estimate bill and an annual bill save back with the same frequency, amountKind, dayOfMonth and anchorDate (both failed before).
- D14 `/next/dashboard` recap preview. Cause: `usePreviewRecap` is a mutation with no `meta`, so every open ran the after-write invalidation (spine, bank-explain, reports, ledger) and posted again. Fix: a query on key `["/api/recap/preview"]`, `staleTime` 10 min, `retry: false` (a retry is a second model call), `meta: OWN_INVALIDATION`; the hook's return shape is unchanged. `queries.ts` was not changed on origin/main (still 3b454106), so no rebase was needed. Whether AI is on is decided by the server (the template path answers when it is off); the client makes one request per open at most. Test: `next/dashboard/recapPreviewQuery.test.tsx` (one POST across two opens, zero invalidations, no retry on failure).
- D20 "Categories to confirm". Cause: the row linked to `/review` (forecast bank-match inbox) and a loading or failed queue counted as 0. Fix: the row links to `/activity/review`, the categorization queue, as a plain anchor because it lives in the app served at the site root, outside this app's `/classic` base (h2budget has no queue screen yet; this is a temporary fallback to the old screen). A queue (and duplicate count) that is loading shows "loading…", one that failed shows "did not load" with Try again; "Nothing is waiting" shows only when both answered. Tests: `next/dashboard/dashboard.test.tsx` (three new cases).
