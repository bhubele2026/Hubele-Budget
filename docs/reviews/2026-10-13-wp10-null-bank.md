# WP10: no bank snapshot, no bank balance (null, never "0.00")

Branch `fin/wp10-null-bank`, from `origin/fin/integration`. WP9 is merged in, and integration 809ec62a after it.

The owner's decision (2026-10-10): with no bank snapshot, the bank balance is **null** on every reader, never "0.00".

- **Implemented:** everything below, on the branch.
- **Tested:** unit, integration and web tests, and the harness `empty` scenario.
- **Deployed:** no.
- **Enabled:** nothing is behind a flag. No AI, SMS, sync or automation setting changed.

## Root cause (base tree)
- Without a snapshot, `computeCashSignalDetailed` reported `bankToday: r2(ledger.bankToday)`.
- That value is the household's starting balance, which defaults to 0. So it read "0.00", or the starting balance passed off as the bank's own figure.
- Three readers passed it on unchanged:
  - the spine's `bank.balance` (`routes/spine.ts`);
  - the cash signal;
  - "Why this number?" (`displayed.bankToday`, `routes/bankBalanceExplain.ts`).
- `/transactions/balances` already answered null per date, with `balanceUnavailableReason: "no_snapshot"`, in `bankLedger.readLedgerBalances`.

## What changed
- **`CashSignal.bankToday`** is `string | null`: null when `ledger.snapshotBalance == null`.
  - The curve (`daily`, `lowestProjected`, `startingBalance`) still runs off the starting balance.
  - `status` stays `no_data`.
  - A balance with no read time keeps its figure, as before.
- **Spec:** `Spine.bank.balance`, `CashSignal.bankToday` and `BankBalanceExplain.displayed.bankToday` are nullable, with descriptions. Codegen; a second run leaves git clean.
- **Server readers:**
  - the spine and the explain route pass null straight through;
  - `bankLedger.readLedgerAnchor` was already null-aware;
  - the Avalanche schedule's narrative facts read `Number(null) || 0`, so 0 for a household with no snapshot. They used to read the starting balance there. This is AI-only, and AI is off.
- **Web:**
  - the explain popover's adds-up check guards null;
  - every reader already renders null as an em dash plus words (`money()`, `moneyFace()`, `bankBalanceView`), never $0.00;
  - fixtures now send null, as the server does.

## Figures that move
- **API, no snapshot:**
  - `spine.bank.balance` "0.00" (or the starting balance) → null;
  - `cash-signal.bankToday` and the explain route's `displayed.bankToday`: same change;
  - `/transactions/balances`: null already.
- **On screen: nothing.** Every surface already said "No bank balance yet" in words, because the web decides "no bank" from the missing snapshot (`bankBalanceView`). The harness reconcile shows the same "no bank balance" rows before and after.
- **Golden snapshots:** exactly three `bankToday` values → null (1800.00 and 2500.00 in the no-snapshot cases, 690.00 in the "time but no balance" case). The curves are unchanged.
