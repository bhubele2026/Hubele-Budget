# F4 — Split by category (2026-10-09)

Branch `restore/f4-splits`, base `02d7fabb` (main with F3b). Parity doc row F4. No server or spec change; `GET/POST/DELETE /transactions/{id}/splits` come from the `features` client, used only from a dialog that loads on first press.

## What was built
- **"Split" button on every Chase and Amex row** (`components/splits/SplitByCategoryButton.tsx`; Chase main rows, Amex desktop rows and the Amex phone list). Chase rows carry `splitCount`, so the button reads "Split ×N" for a split charge; Amex rows come from the plain list (no count), so it reads "Split" and the dialog shows the real state on open.
- **Dialog "Split by category"** (`SplitByCategoryDialog`, lazy chunk of about 5 KB): category + amount per part, "Left to assign / Balanced / Over by" line, Save off until Σ parts = the charge to the cent, "Add a part" stops at `MAX_PARTS` (20), signed amounts on send (the charge's own sign). An existing split opens prefilled for editing, shows "The charge changed since it was split. It counts whole until the parts are rebalanced." when the server marks it `invalid`, and has "Remove split" (DELETE). Refusals say "Nothing changed."
- `lib/splitMath.ts` ported from h2 (`parseCents`, `formatCents`, `chargeCents`, `signedAmount`, `splitState`, new exported `MAX_PARTS`) with its tests plus a MAX_PARTS / Σ case.
- **Labelled apart from the bucket split:** the button is "Split" with the tooltip "Divide this charge between budget categories"; the dialog is titled "Split by category" and says "…it is not the allowance-bucket split on Allowances." The Allowances bucket split (`split-transaction-dialog.tsx`, creates manual rows) is untouched.
- After a save or removal the dialog marks stale: the charge's splits, the transactions list, `/api/budget*` (plus the global write rule: spine, ledger, reports).
- Column geometry: the Chase actions track is 16rem → 19rem and the Amex one 5rem → 8rem (`ledger-grid.ts`) to fit the button; the merchant column is 3rem narrower on a wide ledger.
