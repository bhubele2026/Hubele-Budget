## What was built (revised: row detail, no new button, no widening)
- **Entry points, in each page's existing row detail (no new column, no button on rows):**
  - **Chase:** "Split by category…" in the row's Edit dialog (`TransactionEditDialog`, existing charges only, bottom left beside Save). Pressing it closes the edit dialog and opens the split dialog. The edit pencil is on every Chase row at every width, so desktop and phone are the same path.
  - **Amex:** "Split by category…" in the row's merchant popover (the pencil beside the merchant name, `MerchantRenamePopover`, new optional `onSplit` prop), on both the desktop rows and the phone list. Amex has no edit dialog or menu; this popover is its only per-row detail. It is the same shared popover Chase rows use, but Chase does not pass `onSplit`, so Chase's popover is unchanged.
- **Marker:** a split Chase charge shows a muted "Split ×N" chip (from `splitCount`) in the merchant cell's spare room (`metaNode`, next to the forecast chip); nothing is widened. Amex rows carry no count, so no marker there.
- `ledger-grid.ts` is back to `main`'s values (Chase 16rem, Amex 5rem); the merchant column is untouched.
- **Dialog "Split by category"** (`SplitByCategoryDialog`, lazy chunk of about 5 KB, hosted by `SplitByCategoryHost`, which renders nothing until a charge is chosen): category + amount per part, "Left to assign / Balanced / Over by", Save off until Σ parts = the charge to the cent, "Add a part" stops at `MAX_PARTS` (20), signed amounts on send. An existing split opens prefilled, shows the server's "counts whole until rebalanced" note when `invalid`, and has "Remove split". Refusals say "Nothing changed." After a save or removal it marks stale the charge's splits, the transactions list and `/api/budget*` (plus the global write rule).
- **Labelled apart from the bucket split:** the entry points are "Split by category…" with the tooltip "Divide this charge between budget categories (not the allowance-bucket split)"; the dialog is titled "Split by category" and says it is not the allowance-bucket split on Allowances (untouched).
- `lib/splitMath.ts` ported from h2 with its tests plus a MAX_PARTS / Σ case.
