# Amex household line: the exact unconfirmed part (branch prem/hh-split, from prem/integration 60665d32)

Small money-path change. All amounts here and in tests are synthetic.

## Why
- The Amex Summary line "Adds $X to this week's household plan" shows the cautious pool (`weeklyPlan`).
- The glossary says a cautious figure says how much of it is unconfirmed.
- The web could only say "(may include unconfirmed)": the summary carried no split.

## What changed
- Server `lib/amexSummary.ts`:
  - Each household-window row gets its F2 evidence class, as `moneyPosition.ts` does:
    `evidenceContextOf(window.money, billSuggestionsOf(cash.ledger, window.money.supersede))` + `rowEvidenceOf`.
  - No new read: the window, the money context and the ledger are the ones the summary already loads.
  - Split by `evidenceSplitCents(rows, "week")` and `(rows, "month")` — the breakdown's own call.
  - `householdContribution` adds `weeklyKnown`, `weeklyUnresolved`, `monthlyKnown`, `monthlyUnresolved`.
  - `weeklyPlan` / `monthlyPlan` = the split's `actualCents` = `allowanceSpentCents` (same figure as before).
- OpenAPI `AmexSummaryHouseholdContribution`: the four fields, required. Codegen run; `api-zod` + `api-client-react` (src + dist) committed.
- Web `lib/amexSummaryView.ts` `householdLine(hc, mode, isThisWeek)`:
  - Reads the split from `hc`. The optional `split` arg (Q5 round 2) is gone; no caller passed it.
  - Weekly part: "(includes $Y unconfirmed)" when `weeklyUnresolved` > $0; nothing at $0.
  - Monthly part: says it only when `monthlyUnresolved` > $0.
  - "(may include unconfirmed)" is gone.

## Doubts / not done
- The forecast ledger pairs only checking cash rows, so a bill suggestion never lands on a card row today.
  - The summary still reads the suggestions (same rule as the breakdown), but the test's unconfirmed row is Plaid evidence.
  - Dropping the suggestions would not fail this test; it would only matter if the ledger ever paired card rows.
- `monthlyUnresolved` is 0 by construction today: a monthly-flagged row is the household's own confirmation.
  The field and the words are there for when the rule changes.
- Deploy skew: an old server without the fields makes the line say nothing about unconfirmed (no "NaN").
  API and web ship as one service, so this should not happen.
