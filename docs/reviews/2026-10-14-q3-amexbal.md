# Q3 Amex running balances (branch prem/q3-amexbal, from prem/integration 8a3f88c9)

Web money code + one server fallback + tests. No API spec, schema or codegen change.
All amounts in tests and here are synthetic.

## The bug
- Plaid card rows carry the bank sign: a purchase is negative, a payment positive.
- Workbook rows (`source: "amex"`) store a purchase positive.
- The Amex page walked card rows with the checking rule (`older = bal − amount`, `computeRunningBalances`).
- So on Plaid rows, going back in time, a purchase made the balance RISE.
- Same flaw in the month-end helper (`amexEndingBalance.ts`) and the 12-month chart (`amexBalanceWindow.ts`).
- Pending rows were walked too: a pending hold shifted every posted row's "bal".
- Server `computed` anchor summed the raw amount across both sources.
- Proved first: `accountCardAnchor.test.tsx` failed at the correct value (got $527.16), `amexAnchorRoute` failed (got 61 / −40.65), `amexCardWalk.test.tsx` failed 5/5 on the old page.

## What changed
- New `lib/cardBalanceWalk.ts`: the one card-balance walk for the web.
  - Owed change per row = `normalizeCardAmount` (avalanche-core, the server's card-sign rule). No new sign rule.
  - Posted rows only. Pending rows get no "bal" and move nothing.
  - `walkCardBalancesBack` (from the anchor) and `walkCardBalancesForward` (from the opening). Integer cents.
  - Order = `compareNewestFirst`, the day list's order.
  - `cardWalkNote`: the words under the ledger.
- `lib/amexEndingBalance.ts` `makeAmexBalanceAtEndOf`: reads rows through `cardOwedMoves`; result rounded to the cent.
- `lib/amexBalanceWindow.ts` `buildBalanceWindow`: same rows and signs, sums in cents.
- `lib/runningBalance.ts` `computeRunningBalances`: untouched (checking). The Amex page no longer calls it.
- `pages/amex.tsx`:
  - One card: per-row "bal" from `walkCardBalancesBack` over that card's month rows.
  - All cards: no running balance, no combined chart.
  - All cards: the chart slot shows "Balance by card" (`components/amex-card-balances.tsx`).
  - The slot keeps the chart's viewport trigger, so the 12-month read starts at the same moment.
- All cards: the amount column header reads "Amount" (it read "Amount · Bal").
- `components/amex-card-balances.tsx`: each card by name + ••mask, its current balance (`scope.cards[].owed`, server).
  - Unknown = "—", never $0. Failed = "Card balances did not load." Tap = open that card.
- Server `lib/amexAnchorRead.ts` `computed` fallback: summed per source, each through `normalizeCardAmount`, in cents.

## Pending
- Walk is anchored on posted rows. Pending rows: listed, no "bal".
- Replaced pending rows: a pending row its posted row replaced can never count twice (no pending row is walked).
- The server's pairing (`pairPendingWithPosted`) is not exposed for `/transactions` rows, and the web row has no `createdAt`, so the page cannot name the pairs.
- Does the card's current balance include pending? UNKNOWN for certain.
  - Plaid documents `balances.current` as the balance, and `available` as limit − current − pending outflows: current is typically posted-only.
  - It is issuer-dependent; no fixture can prove it. The walk treats the anchor as posted-only.
