## Rules that hold

- A text goes out only to a number the member **verified** (6-digit code, SHA-256 hash only stored, 10-minute TTL, 5
  tries then locked, 3 starts/day) after **consent** recorded at the moment they ask for the code
  (`consent_text_version`, `consented_at`; the exact sentence is `CONSENT_TEXT`, returned by `GET /recap/settings`).
- STOP-family words (`STOP STOPALL UNSUBSCRIBE CANCEL END QUIT`, whole message, case-insensitive) set `opted_out_at`
  and `enabled=false` for **every verified row with that number** and send one confirmation. `START/UNSTOP/YES`
  clear the opt-out (the recap stays off until the member turns it on). `HELP` answers. A fresh confirmed
  verification also lifts an opt-out (fresh consent).
- Replies to STOP/START/HELP are never blocked by the daily cap.
- Signature check: always in production. With the console or fake provider it is skipped **only** when
  `NODE_ENV !== 'production'`. In production with no token configured every webhook request is refused (403).
- Phone numbers and message bodies never reach logs (`sms.to` / `sms.body` redaction verified by a test that logs
  through the same path list); logs carry a 10-char hash of the number. The inbound body is not stored in production
  (`body_hash` always; `body_preview` ≤160 chars only outside production).
- US numbers only (A2P 10DLC is US-only): `+1` and a valid NANP area code / exchange.

## Owner setup checklist (Twilio)

Everything works in console mode until these are done; nothing is sent and nothing breaks.

1. **Buy one US local number** in Twilio.
2. **Register an A2P 10DLC Sole Proprietor brand**: name, address, and a mobile number that receives the one-time
   code (about $4).
3. **Register one campaign** (about $15 once + $2/month). Use case: *account notifications*. Opt-in description: the
   user turns on Daily Recap in H2, enters their number and confirms a 6-digit code; the consent sentence is shown in
   the app next to the number field (`CONSENT_TEXT` in `src/recap/messages.ts`). Sample message: the test template,
   `H2 test: your morning recap will arrive at 07:00 America/Chicago. Reply STOP to opt out.`
4. **Create a Messaging Service**, add the number as a sender, and set its **inbound webhook** to
   `https://h2budget.onrender.com/api/sms/inbound` (HTTP POST). The status callback is sent with every message by the
   app; nothing to set for it.
5. **Render env vars**: `SMS_PROVIDER=twilio`, `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`,
   `TWILIO_MESSAGING_SERVICE_SID`, `SMS_WEBHOOK_BASE_URL=https://h2budget.onrender.com` (no trailing slash; must
   match the public URL exactly, because the signature covers it). Optionally `SMS_DAILY_SEND_CAP`.
6. Check `/api/healthz`: `"sms":{"provider":"twilio","configured":true}`.
7. Approval takes about 24–48 hours; until then leave `SMS_PROVIDER=console`.

Alternative: **toll-free verification** (2–3 weeks) instead of 10DLC.

## Residuals

1. **`braces` (GHSA-vfj7-8cjw-p6xm, high, ≤3.0.3) has no patched release** (3.0.3 is the latest; the advisory lists
   none) and `http-proxy-middleware` 4.2.0 still depends on `micromatch`. It is recorded as accepted in
   `pnpm-workspace.yaml` `auditConfig.ignoreGhsas` with the reasoning: it sits behind the Clerk proxy, whose patterns
   are fixed in our code; no request data reaches `braces()`. Delete the entry when braces ships a fix. Only removing
   `http-proxy-middleware` (owned by the Clerk proxy) would clear it for real.
2. The "boot logs a warning" for an unconfigured twilio is emitted once, the first time the provider is resolved (first
   send or healthz), not in `index.ts` (outside this package's files).
3. `skip_weekends` is stored and returned but **not enforced** in `sendRecapDelivery`: it needs the household calendar
   and belongs to the recap generator / `recap.tick`.
4. With a Messaging Service, Twilio itself answers STOP/HELP and blocks later sends to that number; our own reply to
   STOP may then fail (21610) and is recorded as a failed `reply` row. Harmless; the opt-out is already stored.
5. The daily cap is global (all households) and counts verification and test texts too; the cap row is `failed`
   (`daily_cap`) so it never counts against itself.
6. The per-member locks are in-process (one Render instance). A second instance would need an advisory lock.
7. `recap_deliveries.recap_id` has no FK yet (no `recaps` table until the generator package).
8. The `sms.inbound` job payload carries the message body in the pg-boss job table until pg-boss retention removes it.
9. `devCode` is returned by `verify/start` only when `NODE_ENV !== 'production'` **and** the console provider is
   active, so local development can finish the flow.
10. The consent sentence (`CONSENT_TEXT`, version `2026-10-v1`) is a draft for the owner to approve before the
    campaign is registered with the same wording.
