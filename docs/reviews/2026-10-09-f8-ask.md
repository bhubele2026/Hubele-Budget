## The `?tx=` mapping

- h2's refs opened `/activity?txn=<id>`, an all-accounts ledger that classic does not have.
- Classic sends every ref, in an answer and in a memory note's evidence, to `/transactions?tx=<id>`: the Chase ledger, which has scrolled to `?tx=` since #488 (CH-09).
- Limit: a ref carries only an id. A ref to an Amex charge lands on Chase, finds no row, and the page opens normally with nothing scrolled. Sending it to the right ledger needs the account on the ref (a server change), so it is left for the owner to decide.

## Amex `?tx=` handling

- `useTxDeepLink` waits until the month is on screen, then scrolls the row into view (`row-amex-<id>` on desktop, `row-amex-mobile-<id>` on a phone; the visible one wins).
- It sets the page's scroll-to-today latch, so that scroll does not pull the view away.
- It strips only `tx` from the URL (`?month=` stays), so a reload does not jump again.
- Fixed in this block: the pulse timer was cleared each time the rows re-rendered, so the focus id could stick. Only unmount cancels it now (new test, mutation-checked).
- Chase also pulses a ring on the row. Amex gets the id back from the hook but draws no ring yet: that needs both row trees, which is C10's row work.
