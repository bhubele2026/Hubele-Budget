# F1 — real card payments never disappear; plan activation is safe (branch fin2/f1-oblig, from fin2/integration 6a32ec83)

Server + avalanche-core + spec/codegen. One web line (compat). No migration. No setting written.

## The bug (fixed)
- Hook "charges" = cards with NO debt row (any status). Hook "spent" = every account.
- Platinum's debt is ARCHIVED: out of the hook, and no minimum (archived debts emit none).
- With no plan the stored $450 hid it. With a plan over budget: Saturday = $0 + Gold only.
- Fixture proof (plan $150, over): pre-F1 Saturday 10/17 = $20; real Amex owed = $120.

## What changed
- **Gate (commit 250049d3, first):** every plan write refuses `409 {code:"plan_unsafe", reason}`, nothing written.
  - Paths: POST + PUT `/allowance-plans`, approved weekly-limit proposal, `PUT /settings` changing weekly/monthly allowance or `weeklyAllowanceOverrides`.
  - Holds while a hook card (a card at an active hook's cadence) has no resolved mode, or the model is off.
  - Request mistakes still answer 400 first. No hook → never refused.
  - Lifts by itself once every hook card resolves (live defaults resolve). `HOOK_OBLIGATIONS=off` restores it.
- **Payoff mode per card** (`cardPayoffMode.ts`): `preferences.amexCardPayoffMode[accountId]`, server-owned.
  - Default: no debt / no ACTIVE debt (archived, paid, zero) → `in_full`; active with APR or minimum → `debt_plan`.
  - Unresolved: active debt with neither; explicit `debt_plan` with no active revolving debt.
  - Unresolved cards are billed like `in_full` (reads low, never high) and hold the gate.
  - Owner-only `PUT /amex/cards/:accountId/payoff-mode` (`null` clears). Web: F4.
  - Exposed: `/amex/summary` `scope.cards[].payoffMode`; `/amex/weekly-payoff` `payoffModes` (additive).
  - `/amex/summary` `planLink` follows the mode: an in_full card answers to its hook, even with an archived debt.
- **Hook amount = incurred + carried + allowanceLeft** (`everydayHooks.ts`, core `hookOccurrenceAmounts`).
  - incurred: own period's purchases − refunds on in_full cards of the cadence (debt-linked or not), less payments.
  - carried: earlier due, unanswered periods' unpaid, moved into the latest due occurrence (labelled both ways).
  - allowanceLeft: plan → max(0, cap − spent) while open; no plan → stored − own purchases, ≥ 0; closed → 0.
  - debt_plan cards stay out. One hook event per occurrence.
- **Card figures, one read** (`readCardPeriods`): per card, per period, same per-row rule as the Amex page.
  - `cardRowOwed` moved verbatim out of `computeWeeklyPayoff`; `/amex/weekly-payoff` cards/totals unchanged.
- **Payment evidence** (core `allocateHookPayments`): oldest obligation first, once.
  - Sources: checking rows no plan used naming the issuer; rows tagged to an in_full card's debt; the card's own payment credits.
  - A card credit + the checking row that sent it = one payment (same cents, checking −5..+2 days).
  - A checking row a debt_plan card's ledger received is that card's, never an in_full card's.
  - Pending → posted once (cash-row pairing for checking; superseded-pending for cards).
  - A payment never pays a week that has not closed on its date (as before F1).
- **No double counting:** `debt:` minimum left out for in_full cards (`expandDebtMin`, `buildDebtMinSchedule`, `resolutionScheduleLookup`), and out of the avalanche population (`activeSimDebts`).
  - Only for an explicit in_full with an active debt, and only when a hook of the card's cadence exists.
- **Sizing window:** hooks sized from the first of last month (was today − 14), so an unpaid week stays owed.
- **`hookReserves`** gains: `storedAmount, incurred, paid, carried, carriedFrom[], carriedTo, allowanceLeft, cards[]`.
  - `amount` keeps its meaning (before evidence/answers) = incurred + paid + carried + left. Curve = amount − paid.
- **Dry run** `POST /allowance-plans?dryRun=1` (same body): governed occurrences before/after with split, 90-day low point before/after, gate reason. Nothing written.
- **Kill switch** `HOOK_OBLIGATIONS=off`: pre-F1 card-band model back whole (incl. minimums) + gate shut.

## Measuring "unpaid" (the choice)
- Per occurrence, from evidence. Never the card balance.
- Why not the balance: point-in-time sync value, no period split, holds pre-window debt (archived Platinum's old balance) — would move a paydown onto one Saturday.
- Purchase once (its period; pending→posted once). Refund nets the period it is dated in. Payment allocated once.

## Doubts / left undone
- An untagged Amex payment that really paid Blue (debt_plan) and that no plan claimed is allocated to in_full weeks unless Blue's own ledger shows the credit. If Plaid sends no card-side credits, that reads high by the amount. Live card credits unverified.
- Card credit ↔ checking pairing is a heuristic (equal cents, −5..+2 days). A wrong pair still counts the card's payment once.
- Carry window = first of last month. A week paid from an unseen account with no card credit stays "unpaid" up to ~6 weeks (reads low).
- Mid-week prepayment of the open week does not reduce its reserve until the week closes (as before F1; reads low).
- A refund larger than a period's purchases floors at 0 per card (as the card page); the excess credit is not carried.
- An in_full card at a cadence with no hook is paid by no event (pre-existing). Its minimum is kept in that case; the gate only looks at hook cadences.
- Kill-switch path is pre-F1 except: a moved-date Review answer no longer competes for a payment row.
- `LedgerPlanFate` gained `carried` (internal). Banking review does not list it (F2 owns `bankingReview.ts`, untouched).
- Paid weeks older than 14 days are now sized and listed in `overdueAssumedPaid` (more "paid on evidence" lines on the register).
- `PUT /allowance-plans/:id` checks the gate before existence: in a gated household a missing id answers 409, not 404.
- Dry run uses the 90-day horizon (the spine's low point) and lists every governed occurrence in it (13 weekly).
- Web (F4): plan dialog with the dry run, Amex "How this card is paid" toggle, forecast line words.
