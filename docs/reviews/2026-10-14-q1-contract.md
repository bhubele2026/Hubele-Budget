## 3. Bank confidence
- `spine.bankConfidence` (lib/bankConfidence.ts):
  - `fetchedAt`: when the bank last told us anything (`lastHeardAt`, the freshness rule's own instant).
  - `bankBalance` / `bankAsOf` = `bank.snapshot`; `h2Balance` = `bank.balance`.
  - `check {status, reason, stale, staleReason, checkedAt, difference, direction}` = the review's `balanceCheck` (forecast account). At most one query.
  - `pendingCount`: counted pending rows on the forecast account, through today.
- `readLedgerTotals.pendingCount` (a replaced pending row is not one); Banking `cashFlow.pendingCount`.
- One freshness rule (bankFreshness.ts):
  - `lastHeardAt` + `unrecoveredFailureAt` (one read for any number of items; `computeBankFreshness` now uses it too).
  - `plaidItemFreshness`: `state` ok · stale · refresh_failed · needs_reconnect · never.
  - GET /plaid/items: each item carries `freshness` (never reads `lastSyncError`).

- `bankConfidence` is top-level on the spine (as asked). Its keys say "balance", so the landing-law key scan skips it like `bank` and a new test holds it to the bank law.
- `fetchedAt` = last heard (later of the balance read and the last sync for Plaid). Staleness stays on `bank.stale`.
- Spine cost: bankConfidence adds the review's forecast-account reads (accounts, register, totals, ≤1 check query, settings). In parallel with the rest; not measured on production data.
- GET /debts reads the card roster only when a debt links an account. GET /plaid/items: one more query.
- Dry run: the badge count (`computeReviewCount`) is not overlaid (not in the figures).
- `needs_reconnect` also covers PENDING_EXPIRATION (not stale): the web's reauth rule, kept.
