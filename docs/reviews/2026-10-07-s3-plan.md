## The owner's decision

The plan's purpose: control spending, get out of debt. Plan is where the household sets the number that controls spending (the weekly limit), sees the debt plan as a range and as % paid, and keeps the bills and category lines that feed both.

## Laws kept

- **No amount owed:** the debt hero is "41% paid" and nothing else; `plan.test.tsx` smuggles `balance`/`owed`/`totalOwed` onto the spine and a balance into `comparison.detail`, and asserts neither reaches the page, and that the hero region and the page match none of the owed words. A per-debt balance appears only inside that debt's own sheet.
- **Ranges only:** "Debt-free around Mar 2029 to Nov 2029" and "Projected interest $3,480 to $4,650"; an open-ended latest month reads "or later". The test asserts no "debt-free on …" string anywhere. The comparison table shows a debt-free month per strategy because the brief asks for it; it is a month, never a day.
- **Claim wording:** logging a payment says exactly "Logged. It counts as paid once the bank shows it."; when the server says the payment cleared the debt, " <name> is paid off." follows.
- **One figure-xl per page** (asserted on Week and Debt).
- **Owner only:** a member never sees the controls; a 403 from the server is answered "Only the household owner can change this."

## For the lead to reconcile with S2

## Residuals

- Brief said cadence "once"; the server's value is `onetime`. The sheet uses `onetime`.
- Brief said Income · Bills · Subscriptions by kind; the data has only `income` and `bill` (no `subscription` kind exists in the server or classic). Subscriptions shows only if a row ever has that kind.
- A bill with a `debtId` is editable like any other, as in classic.
- The week hero is the shared plan's amount (as briefed); the meter uses Today's `weeklyLimit`, which prefers the position's `weekCap` (override-aware). They differ only when a per-week override is in force.
- Member plans can only be edited, not created: `PUT /allowance-plans/:id` takes an id and there is no create route. A member without a plan row has no line.
- "Use the suggestion" PUTs the suggested amount; the server writes `source: "owner"` through its one writer, so the word afterward is "set by you" and the "matches the suggestion" line replaces the button.
- The extra: when the extra's source is a budget line or the budget's net, Save sends `extraSource: "manual"` with the amount (the hint says so beside the field). Otherwise `manualExtra` alone would not change the plan.
- "Safe up to" reads `GET /avalanche/extra`'s `availableMoney` (the budget headroom the classic slider uses); the warning past it does not block Save.
- Pinning (month and line) is not ported. A pinned line reads "pinned" in its disclosure.
- The Plaid liability link flow is S4; the debts section links to `/household`, which is a Not-found page inside the shell until S4 lands.
- "Afford this" does not exist on Today in S1, so the wish list says "Afford this arrives with the next update." with no link.
- Plan writes also mark the Plan reads stale (`invalidatePlanWrite`: allowance plans, recurring items, bills summary, debts, debt plan, avalanche, budget, forecast, money). The app-wide rule does not cover those.
- The debt payment sheet's `account` and `notes` (in the API) are not asked for.
- `/design/plan` saves reach for the API and answer with an error; it is a look-only page.
