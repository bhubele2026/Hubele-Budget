## The owner's ask
- "Same with Amex": review a card and see at once what was not in the plan.
- Owed now · purchases · payments and credits apart · plan only where the card has one · purchases to resolve.
- A household allowance is never one card's budget.

## What changed

### 1. `classifyCardCredit` (avalanche-core, pure)
- One card row → `purchase | other_charge | refund | payment | other_credit` (null for $0.00).
- purchase = `classifyOutflow(…).kind === "spend"`; refund = `classifyRefund` — the payoff's own tests.
- payment = the payment half of `isRefundCandidate`'s exclusions: card-payment flag, debt tag/category, Plaid LOAN_PAYMENTS, issuer phrase, payment words (`readsAsPayment`).
- `computeWeeklyPayoff` now bills through it (provably the same tests; 6,000 seeded rows pin the equivalence).
- The Amex-only card-ledger refund rule is untouched (S6 owns it).

### 2. `GET /api/amex/summary?accountId=<card | all>&from&to[&rowsPerGroup≤50]`
- Tag `amex, features` → hook in `@workspace/api-client-react/features` (off the landing chunk).
- `scope`: the card (name · ••mask · institution) and `cards[]` — "all" lists EVERY Amex card, debt-linked included.
- `owed {current, statement, asOf, source}`: `resolveAmexAnchor` = GET /amex/anchor's own answer.
  - One card: its Plaid balance, else its debt row, else unknown (null, never 0).
  - "all": the combined anchor (the figure the page shows today). Each card's own figure is on `cards[].owed`.
  - `statement`: the latest `debt_statements` row of a debt-linked card; else null.
- Buckets — every row on the card(s) in the period, once (replaced pending rows out):
  - `purchases {amount, count, reimbursable}` (reimbursable still counts, flagged)
  - `refunds` · `payments` · `otherCredits` · `otherCharges` · `notMine` (`amexExcludedTxnIds`)
- `householdContribution {weeklyPlan, monthlyPlan, unfiled, link}`: `loadAllowanceWindow` + `allowanceRowOf` + `allowanceSpentCents` over the card's rows — the breakdown's `account=` read.
- `planLink` (flat, `kind` decides):
  - `debt`: debtId · name · minimum (null when "0") · `avalancheRank` · status
  - `weekly_hook` / `monthly_hook`: the hook's payoff for the period holding `to`, its date, `basis` plan | stored_amount (the ledger's `hookPayoffs`)
  - `none`
- `needsAttention`: purchases to resolve, one group each, first wins: unplanned (UN) · unfiled · uncategorized (filed, no category).
  - Rows `{id, date, displayName, amount, pending, category, flags, card{accountId, name, mask}}`, largest first, ≤ rowsPerGroup, `truncated`.
  - Placed by the allowance window (effective filing: a posted row carries its pending row's filing).
- `limitations[]`: `tracking_start:2026-05-01` when `from` was clamped.
- Refused: bad date, from > to, from after today, to before tracking, > 366 days (400); not an Amex card of the household (404).

### 3. `GET /amex/weekly-payoff` + `debtLinkedCards[]`
- `{accountId, name, mask, debtId, brand, cadence, displayName}` for each card `cards` leaves out.
- `cards`, `combinedWeekCharges`, `combinedStatementBalance` unchanged.

### 4. Moves (no new logic)
- `resolveAmexAnchor` (lib/amexAnchorRead.ts): the GET /amex/anchor handler body, verbatim; the route calls it.
- `displayNameOf` / `loadMerchantAliases` exported from periodBreakdown.ts (its rows use them too).
- `avalancheRankOf` (avalancheSim.ts): `targetIndex` repeated — the rule `resolveAvalancheTargetDebt` uses.
- `amexCardLabel` (avalanche-core): the card band's name chain (household name → tier word → Plaid name).

## Deviations from the brief (code wins, intent kept)
- `classifyCardCredit` has a fifth kind, `other_charge`: a card charge the spending rule leaves out (Ignore, transfer, debt row). Without it those rows fit no bucket. Response bucket `otherCharges`.
- `planLink` is one flat object (as S3's `scope`), not a union. Added `monthly_hook` (the Blue card is billed by the monthly hook), `basis`, `status`.
- `scope` is flat too: `kind` + identity (null for "all") + `cards[]` (one entry for a card).
- "all" `owed` = the combined anchor, not a sum of cards (no figure moves). `cards[].owed` adds each card's own.
- "all" `planLink`: the hook that bills the band's cards (weekly first), else none.
- Extra fields: `owed.source`, `purchases.reimbursable`, `otherCharges`, `cards[]` (brand, cadence, debtId, owed), row `card.accountId`, per-group `truncated`, `limitations[]`.
- `debtLinkedCards` adds `brand`, `cadence`, `displayName` (the card tabs name a card from them). Optional in the spec (always sent), so parallel web fixtures typed `AmexWeeklyPayoff` keep compiling.
- Tests: the two-card case is its own household (three cards) in a new test file; the B4 scenario (one card) got the summary at every step instead of a second card, which would have moved every B4 figure.
- A web test file (test only) pins the card name chain; no screen changed.

## Open / doubtful (recorded, not fixed)
- **Effective filing:** the payoff (so `purchases`) reads the raw posted row; spending facts and the allowance window give a posted row its pending row's filing. Differs only when a pending row was filed Ignore / transfer / to a debt and its posted row arrived bare.
- **"Not mine" rows** are out of the payoff but in the money position, breakdown and spending facts (they never read `amexExcludedTxnIds`). The fixture shows it: Platinum `weeklyPlan` 560.00 includes the 300.00 not-mine charge.
- **Debt-linked card purchases** count in the household week (position, breakdown) but not in the hook's charges (`combinedWeekCharges` drops debt cards). Shown, not changed: Gold `householdContribution.weeklyPlan` 250.00.
- **"all" owed** leaves out a card named Delta (the anchor's #gold rule) and can fall back to a name-matched debt, the saved anchor or a computed sum. B4 shows a card whose own owed is unknown (null) while "all" is 500.00 from a name-matched, unlinked debt.
- `AmexAnchor.source` in the spec lacks `plaid`, which the route sends. Pre-existing; not changed (outside this brief).
- Workbook rows (`source: amex`, no Plaid account) are in no card scope — as in the payoff.
- Re-link twin `plaid_accounts` rows would show as two cards (as in the payoff).
- `avalancheRank` uses row balance and APR only (`resolveAvalancheTargetDebt`'s rule), not the pending-netted balance; a debt with a $0 minimum still ranks.
- needsAttention amounts are gross purchases; refunds net only in `householdContribution`. The system "Uncategorized" category counts as uncategorized here (`classifyOutflow` calls it categorized).
- Cost: one forecast ledger per request (as S3/S4), plus one anchor read per card in scope (≤ 3).
- The tier words live twice (core + web `amexBrand.ts`), pinned equal by test; W4 can import core's.
